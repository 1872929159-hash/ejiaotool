"Fetch origin"

② 开分支对 WorkBuddy 说：

feature/我的名字-改什么"
→
③ 改代码对 WorkBuddy 说需求

4 协作约定（避免撞车）

📌 分支

  • main = 唯一主干，合并后自动部署。约定 不可直接推 main，必须发 Pull Request
  • 你的分支：feature/名字-功能，如 feature/zhangsan-改按钮颜色
  • 一次只改一个功能，改完合并再开下一个
  • 开改前一定先 Pull！否则合并必冲突

🗂️ 文件分区

整个网站就一个文件 tools/合规检测工具.html。约定 5 个区，每次只动一个，PR 标题注明：

A 区CSS 样式 / 颜色 / 字体 / 布局如 "[A区] 按钮改成暗红色"
B 区763 条词库数据（一般别动）加新词需单独开 PR 和负责人确认
C 区检测逻辑（runCheck 等）
D 区AI 复核逻辑（runAiReview 等）
E 区UI 文案 / 标题 / 提示语

不同区同时改 ≈ 不冲突。同区冲突 → 让 WorkBuddy 处理。

5 给 WorkBuddy 的话术（照着说就行）

目标对 WorkBuddy 这样说
改配色把检测按钮颜色改成 #993556，清空按钮改成灰色
改文案把顶部标题从「京东营销合规」改成「多平台营销合规检测」
加功能在检测结果下面加一个「导出报告」按钮，点击下载 txt
改 AI 提示词把 AI 复核的提示词改成更严格的合规标准，加上「检查是否涉及虚假宣传」
同步代码先 pull 一下 main 最新代码
开分支从 main 开 feature/zhangsan-改按钮颜色
提交推送把当前改动提交，消息写「调整按钮配色」，推送到我的分支
发 PR帮我在 GitHub 上发 Pull Request，标题写 [A区] 改按钮配色
处理冲突帮我解决合并冲突

6 GitHub Desktop 操作速查

你要做的点哪里

查看改了什么左侧面板 Changes 标签页，勾选/取消勾选文件

7 常见问题

双击 start.bat 没反应？没装 Node.js 或装了没重启电脑。安装 LTS 版后重试。实在不行直接用公网看效果。
push 推不上去？通常是网络问题。换手机热点试试，或让负责人用 GitHub API 脚本上传（仓库里已备好）。
合并冲突了？别慌。对 WorkBuddy 说「帮我解决合并冲突」就行。
改完公网怎么没变？① 确认已合并到 main（不是只在你自己分支）；② 等 30-90 秒；③ Ctrl+F5 强制刷新。
改坏了怎么办？只要没合并到 main 就没事——删掉分支重来。main 进不了坏代码。
想看某次改动的公网效果（没合并前）？去 GitHub 仓库 → 你的 PR 页面 → 找 EdgeOne 自动生成的 Preview URL（如有）。或者自己本地 start.bat 看。
